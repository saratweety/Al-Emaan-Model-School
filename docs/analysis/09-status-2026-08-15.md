# Status Check — 15 Aug 2026

This supersedes the `00-08` audit files (dated 13 Aug 2026), which are now badly stale — most of what they list as "missing" has since been built. This file reflects the codebase as it stands right now, verified by reading the actual source and querying the live database directly (not guessed from the UI).

**Scope note:** teacher check-in / attendance tracking (fingerprint or geolocation-based) is intentionally excluded from this list — it's a separate, already-scoped feature waiting on school location data, not a "leftover" bug.

## What's fully real now

Built or fixed this session, confirmed against live data:

- **Notices** — principal CRUD (create/edit/delete/detail page), teacher view, parent view, unread-count badges on both sidebars, `announcement` type added.
- **Homework / Diary** — subject teachers restricted to subjects they actually teach; class teachers can post a class/vacation diary; principal's Homework Diary page is fully data-driven; parent sees both homework and diary entries.
- **Timetable** — principal, teacher ("My Timetable"), and parent views all show real schedules with teacher names per period.
- **Subjects** — class-wise assignment (Play–Prep, 1–8, "select all", per-subject class editing).
- **Parents module** — real Edit Parent (name/phone/email, including login email), row-menu fixed to no longer trigger a phantom scrollbar.
- **All three dashboards** (`/dashboard`, `/teacher`, `/parent`) — every stat card, notice list, and today's-schedule widget now reads from the database. School Timing has a real backing table (`school_settings`) with a working edit form.
- **RLS fixes** (real, previously-silent bugs): teachers can read `notices` and `subjects`; parents can read `academic_sessions` — this last one was the root cause of the "class shows Unassigned" / "attendance not shown" reports, since almost everything on the parent side depends on knowing the current session.

## A systemic risk worth flagging

Three separate bugs this session (`notices`, `subjects`, `academic_sessions`) turned out to be the same root cause: a table had RLS policies for some roles but not others, so a query silently returned empty instead of erroring — making a correctly-written page look broken for no visible reason. It's very possible other tables have the same silent gap for a role that just hasn't been tested yet. Worth a systematic pass — for every table, check there's a `SELECT` policy for every role that has code querying it — rather than waiting to trip over each one individually.
